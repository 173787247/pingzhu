# 09 · 资料层综合建议（四份调研的汇总）

> 写给下一个接手的人。四份独立调研（`research/05`–`08`，约 3,350 行）的结论
> 在这里收敛成**一个可执行的动作**，以及**一组实测后决定不做的事**。
>
> 日期：2026-10-01 ｜ 使用者定位：台湾与海外的注音使用者（台湾仍用注音教学）
>
> ★ **2026-10-01 更新：本文原推荐的「动作 A：换单字频次来源」经实测后撤回。**
> 撤回的理由与实测数字见第五节 —— 请先读那一节，不要直接照着做。

## 一、一句话结论

**不要换字频来源。** 实测显示换与不换的差别在一个数字键的 0.4%，
而动它要重录 fixture、改 6 个实作 —— 这违反本专案自己的纪律（不为了动而动）。

**真正该做的是**：向国教院争取《三等七级词表》的书面授权（台湾语域权威，
词表自带注音），以及**修好基准的抽样偏差**（已做）。

---

## 二、问题有多大（实测，不是估计）

平注现用的字频继承自 McBopomofo。四个来源逐一实测的对照：

| 来源 | 見 | 建 | 谁胜 |
|---|---|---|---|
| **平注现用**（McBopomofo 衍生 LM） | −3.456 | **−3.333** | 建 |
| `tsi.csv` 现行 libchewing（频次栏） | 25,457 | 15,457 | 見 1.65× |
| `tsi_unigram.arpa`（chewing_v4） | −3.3724 | −3.5890 | 見 1.65× |
| 国教院《台湾华语文能力基准汉字表》 | 1,334/百万 | 628/百万 | 見 2.12× |
| Unihan `kHanyuPinlu` | 3,613 | 1,732 | 見 2.09× |
| **`phrase.occ`（★ 与平注同源的语料）** | **14,027** | **18,620** | **建 1.33×** |

**★ 最后一行是决定性的。** `phrase.occ` 与平注现用的 `WebData.ts` 出自同一个
repo、同一批语料 —— 也就是说**平注的「建 > 見」与它自己的语料一致，它没有错**。

所以先前「平注继承旧资料、把排序弄反了」的判断**是错的**。多数来源说見高，
是因为**它们量的是不同的东西或不同的语域**，不是因为平注错了。**这是语域的
函数，不是语言事实。**

反例同样合理且更能说明问题：

| 来源 | 見 | 建 | 语域 |
|---|---|---|---|
| SUBTLEX-CH（大陆简体字幕） | **1** | 9,772 | ✗ 見 全语料只出现 1 次 |
| FineFreq 2013–24（网页） | 98,171,021 | 1,072,870,186 | 建 10.9× |

**SUBTLEX-CH 是繁体使用者最容易踩的坑**：它看起来是权威中文字频表，
但语料是简体字幕，对繁体字形几乎是空的（`見` 与 `裡` 都只出现 1 次）。

## 三、为什么「只换单字频次」也救不了

### 原先的推理

```
单音节 447 例 · 首选对 24 (5.37%)   ← 字频单独决定答案
多音节 2553 例 · 首选对 2306 (90.33%) ← 字频影响不到
```

看起来靶子很清楚：单音节的 5.37% 靠字频，换掉它就能改善。

### 实测：换与不换的差别

用 `tsi_unigram.arpa` 的分数替换单字分数（只动单字，多字词不动），
同一个种子、同一批样本：

```
                   首选        额外按键
现用               11.82%      0.8818
换 ARPA 聚合        12.20%      0.8780      ← 改善 0.4%
```

**0.4% 的额外按键，不值得动资料层。**

### 而单音节低是本质，不是缺陷

一个读音对应几十个字（ㄐㄧˋ 有上百个），没有上下文时猜哪个都是猜。
**使用者本来就是浏览候选表**，不指望输入法猜中。所以那 5.37% 不是一个
有待修复的数字。

## 四、★ 本轮真正做成的事：修好基准的抽样偏差

**基准原本对语言模型均匀抽样**，于是 21,786 个单字里每个的抽中机会相同。
但真实分布极不均 —— 实测：

```
真实字频分布      最高的 10% 占出现量 98.1%
基准抽到的单字    中位数排名 第 7,228 名 / 共 21,786
                  落在前 100 高频字里   1 / 447  (0.2%)
```

**所以它测的是「引擎能不能叫出一个生僻字的名字」** —— 那不是任何人要它
做的事，而报出来的数字会被当成解码品质。

改成按词条自身频率加权（权重用模型自己的对数概率，不需要第二份语料）：

```
                    修前        修后
单音节样本           447         386
多音节样本         2,553       2,614
top-1 正确率       77.67%      82.20%
  单音节            5.37%       5.70%
  多音节           90.33%      93.50%
同音歧义             670         534
```

**多音节的 93.50% 才是真实使用的主体**（真实打字里多音节占绝大多数）。

## 五、★ 撤回的推荐与它的理由

**本文原推荐「动作 A：单字频次改由 `chewing_v4` 的 unigram 排序」，现撤回。**

撤回经过三次自我更正，都记下来以免重走：

1. **原先的理由**：平注把「見/建」排反了 → **错**。`phrase.occ`（同源语料）
   显示 建 18,620 > 見 14,027，平注与自己的语料一致。
2. **中间一次判断**：「ARPA 是字级聚合分数、会跨读音污染，所以方法错」
   → **也错**。使用者的目标是**字形**不是读音，所以「这个字形整体多常用」
   才是对的信号。（例：打 ㄆㄧ 时「被」比「批」更该排前面。）
3. **最终判据**：实测换与不换的差别是 0.4% 的额外按键 → **不值得做**。

**如果日后有人想再试这条路，请先重跑这个测量**：替换单字分数，比较
「单音节额外按键」这一栏。达标线应该是**显著**下降，不是 0.4%。

## 六、还可以做的两件事

### 动作 B（值得花力气）：向国教院争取书面确认

```
目标一   《台湾华语文能力基准汉字表》  3,100 字，书面／口语两套频次
目标二   《三等七级词表》            14,420 词，★ 全带「参考注音」
         （词库 ＋ 词频 ＋ 注音三合一 —— 对我们比汉字表更有价值）
去函     onile@mail.naer.edu.tw   （研究员另附 corpus@mail.naer.edu.tw）
依据     院级《政府网站资料开放宣告》：「无偿、非专属，得再授权……
         开发各种产品或服务……无须取得本机关之书面或其他方式授权」
★ 但有三方张力，必须问清：
         ① bcoct 子系统页尾写「版权所有 All rights reserved」
         ② 同一语料在数发部 TAIC 上标「仅授权 AI 训练使用」
         ③ 院级宣告有「专人专案撰文须经同意」例外
```

**为什么值得**：它是**台湾正体字语域 ＋ 语料 1999–2018 ＋ 有量化数字**，
且词表自带注音。**《三等七级词表》对注音输入法的价值比汉字表更高** ——
词库、词频、注音三合一。

**但先解决授权再谈用法**：汉字表只有 3,100 字，我们的单音节相异单字有
21,477 个。而授权的三方张力不解决，它连进仓库都不行。

**词表另有一个已知缺口**：汉字表有 **33 组异体字合并**（`台／臺`、`裡／裏`、
`麵／麪`、`著／着`、`鑑／鑒`…），**无法回答这些字的优先序**，需另行处理。

### 动作 C（若要再查来源时）：量一致率，不要争论谁对

**★ 但先看清一件事：来源之间的分歧不等于谁错。** 本轮的教训是每个来源
量的是不同的东西（字级聚合 vs 每读音、不同语域、不同年代），所以「哪个对」
这个问题本身问错了。要比较就比**按键代价**，不是比排序。

如果仍想交叉验证：

```
取 data/bopomofo-chars.tsv 每个读音的所有候选字
分别用「国教院 / Unihan kHanyuPinlu / chewing_v4」排序
量出【第一候选一致率】
三者一致的读音 → 分歧无关紧要
三者分歧的读音 → 人工复核（数量应该有限，可枚举）
```

**Unihan 的限定**：`kHanyuPinlu` 的繁简数值**互相复制**（2,562 对里 2,546 对
完全相同），繁体没有独立统计。所以它只能当**授权最干净的验证点**，不能当主力。

## 七、明确不要用（全部读过原文）

| 来源 | 为什么不行 |
|---|---|
| **中研院全体系**（ASBC、口语语料库、CKIP 词库、广义知网） | 协议第五条明文禁止「字/词频统计」入商业产品 ★ **这同时封死了「自己统计、只散布结果」这条规避路线** |
| **ACLCLP 发行的全部语料** | 需身分证明＋言明不作商业用途＋签约＋付费 |
| **国科会数位典藏 NDAP** | 限个人及非商业目的 |
| **Jun Da 字频表** | 明文禁止商用 |
| **wordfreq 资料** | CC BY-SA 4.0 传染；且把 271 个繁体字在 128 个合并组里抹平（`裡`＝`里`、`麵`＝`面`、`臺`＝`台`）；作者明文拒绝转 CSV；已停止更新 |
| **SUBTLEX-CH** | 简体字幕语料，繁体字形几乎为空；原站 404，许可不传递 |
| **Google Books Ngram 中文** | 实测只有 `chi-sim`，**没有繁体** |
| **THUCTC** | GitHub API 报 MIT，README 却要求商业洽谈 ★ 只看 SPDX 字段会得到相反结论 |
| **腾讯词向量** | 同一句里「CC BY 3.0」＋「for research purpose only」自相矛盾，取严＝限研究 |
| **搜狗** | 付费＋禁止转散布；实验室已下线 |
| **哈工大 LTP／CASIA／SIGHAN** | 企业／商业一律付费或限研究 |
| **rime-ice／fcitx5-table-extra／libpinyin** | GPL-3.0 |
| **北语 BCC（62 亿字）** | ★ 授权条款**未取得** —— 中国这边唯一值得去信确认的大规模字频入口，确认前不可用 |

## 九、这件事的边界

**不做**：换字频来源（第五节，实测只差 0.4%）、整份词表迁移（会掉语汇，
自检 159/257）、bigram 接入（两份模型词表差异过大）、符号表与许氏键盘
（与资料层无关；许氏还需要新增有状态的按键层，`keyboard.rs` 的注释警告过）。

**验收的唯一标准**：**按键代价**下降，且没有新增打不到的字。
不看首选正确率 —— 来源之间的分歧常常只是量法不同，把它读成进步或退步
是本轮踩过的坑。

**当前的诚实数字**（加权抽样后）：

```
多音节  2,614 例 · 首选对 2444 (93.50%)   ← 真实使用的主体
单音节    386 例 · 首选对   22 ( 5.70%)   ← 本质如此，使用者浏览候选表
合计    3,000 例 · 首选对 2466 (82.20%)
```
