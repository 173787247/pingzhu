# 09 · 资料层综合建议（四份调研的汇总）

> 写给下一个接手的人。四份独立调研（`research/05`–`08`，约 3,350 行）的结论
> 在这里收敛成**一个可执行的动作**，以及一条**不该做的事**。
>
> 日期：2026-10-01 ｜ 使用者定位：台湾与海外的注音使用者（台湾仍用注音教学）

## 一、一句话结论

**换掉「同音字谁排第一」这一层的数字 —— 但只换单字频次，不整份换词表。**
数字来源用 `libchewing-data` 的 `dict/chewing_v4/`（CC BY 4.0，今天就能做）。
同时写一封信向国教院争取《汉字表》与《三等七级词表》的书面确认（台湾语域权威）。

## 二、问题有多大（实测，不是估计）

平注现用的字频继承自 McBopomofo，而它的根源是 **libtabe 的 `tsi.src`（1990 年代
台湾语料）**。四个来源逐一实测的对照：

| 来源 | 見 | 建 | 谁胜 |
|---|---|---|---|
| **平注现用**（McBopomofo 衍生 LM） | −3.456 | **−3.333** | ✗ 建 |
| `tsi.csv` 现行 libchewing（频次栏） | 25,457 | 15,457 | 見 1.65× |
| `tsi_unigram.arpa`（chewing_v4） | −3.3724 | −3.5890 | 見 1.65× |
| `bigram_p50.arpa` unigram 段 | −3.5661 | −3.6597 | 見 |
| 国教院《台湾华语文能力基准汉字表》 | 1,334/百万 | 628/百万 | 見 2.12× |
| Unihan `kHanyuPinlu` | 3,613 | 1,732 | 見 2.09× |

**六个来源里五个说「見 > 建」，只有我们现用的那一个说「建 > 見」。**
所以问题出在**我们继承的那一份旧**，不在上游。

**★ 但要注意这是语域的函数，不是语言事实。** 反例同样存在且合理：

| 来源 | 見 | 建 | 语域 |
|---|---|---|---|
| SUBTLEX-CH（大陆简体字幕） | **1** | 9,772 | ✗ 見 全语料只出现 1 次 |
| FineFreq 2013–24（网页） | 98,171,021 | 1,072,870,186 | 建 10.9× |

**SUBTLEX-CH 是繁体使用者最容易踩的坑**：它看起来是权威中文字频表，
但语料是简体字幕，对繁体字形几乎是空的（`見` 与 `裡` 都只出现 1 次）。

## 三、为什么只换单字频次

### ★ 验收标准（这一条决定一切）

**资料层改动的验收标准是「按键代价下降」，不是「首选正确率上升」。**

```
使用者要的字符 → 必须能用按键打到（候选表里有）      ← 硬需求
不用管它排第几 → 排第一省一个键，排第十多按一个键    ← 软成本
```

### 实测：字频只能影响单音节

```
单音节   447 例 · 首选对  24  (5.37%)  ← 字频单独决定答案
          · 想要字在第一页 181 (40.49%)
          · 要翻页         266 (59.51%)   ← ★ 0.405 键/例，这是靶子
多音节 2,553 例 · 首选对 2306 (90.33%)  ← 字频影响不到
```

多音节的竞争者是**同音词**（另一个真词、同读音），不是同音字 —— 换字频动不了它。

**★ 基准原本测不到这件事**：`buildTestSet` 原本只抽 2–4 音节的词，单音节
被整个排除。已修（`engine/bench-lib.mjs`）。修前 top-1 报 91.39%，修后
**77.67%** —— 后者才是诚实的数字。

### 实测：整份换词表会退步

`research/tools/bigram-trial.mjs` 的 runtime 自检（unigram 基线须复现引擎选择）
只过 **159/257**。原因是两份词表规模差太多：

```
libchewing unigram  111,601 条
平注现用            169,604 条
```

所以**整份迁移是另一次资料层工程，而且会掉语汇** —— 本次不做。

## 四、可执行的动作

### 动作 A（今天可做）：单字频次改由 `chewing_v4` 排序

```
来源   libchewing-data  dict/chewing_v4/tsi_unigram.arpa
授权   CC BY 4.0（该目录 README 逐字自述）★ 可商用可改作
规模   147,742 条 1-gram，其中 18,769 个单字
用法   只取单字条目，覆盖我们单音节读音下的首选排序
不改   词表、词频、读音 —— 都不动
验收   单音节 0.405 键/例 是否下降，且没有新增打不到的字
```

**授权注意**：同一个 repo 的 `dict/chewing/*.csv` 档头写的是 **LGPL-2.1-or-later**
（四个档一致，日期新到 2026.3.20）。**只能用 `chewing_v4/`。** 详见
`docs/04-data-and-licensing.md` 的专节。

### 动作 B（值得花力气）：向国教院争取书面确认

```
目标一   《台湾华语文能力基准汉字表》  3,100 字，书面／口语两套频次
目标二   《三等七级词表》            14,420 词，★ 全带「参考注音」
         （词库 ＋ 词频 ＋ 注音三合一 —— 对我们比汉字表更有价值）
去函     onile@mail.naer.edu.tw   （研究员另附 corpus@mail.naer.edu.tw）
依据     院级《政府网站资料开放宣告》：「无偿、非专属，得再授权……
         开发各种产品或服务……无须取得本机关之书面或其他方式授权」
★ 但有三方张力，必须问清：
         ① bcoct 子系统页尾写「版权所有 All rights reserved」
         ② 同一语料在数发部 TAIC 上标「仅授权 AI 训练使用」
         ③ 院级宣告有「专人专案撰文须经同意」例外
```

**为什么值得**：它是**台湾正体字语域 ＋ 语料 1999–2018 ＋ 有量化数字**，
且词表自带注音。但**它不是替换品**：汉字表只有 3,100 字，我们的单音节相异
单字有 21,477 个（覆盖率上限 14.4%）—— 它是**排序覆盖层**，而且要先解决授权。

**词表另有一个已知缺口**：汉字表有 **33 组异体字合并**（`台／臺`、`裡／裏`、
`麵／麪`、`著／着`、`鑑／鑒`…），**无法回答这些字的优先序**，需另行处理。

### 动作 C（低成本交叉验证）：三方排序一致率

研究员建议的做法，我认同 —— **不要争论哪个来源对，去量一致率**：

```
取 data/bopomofo-chars.tsv 每个读音的所有候选字
分别用「国教院 / Unihan kHanyuPinlu / chewing_v4」排序
量出【第一候选一致率】
三者一致的读音 → 直接采信
三者分歧的读音 → 人工复核（数量应该有限，可枚举）
```

**Unihan 的限定**：`kHanyuPinlu` 的繁简数值**互相复制**（2,562 对里 2,546 对
完全相同），繁体没有独立统计。所以它只能当**授权最干净的验证点**，不能当主力。

## 五、明确不要用（全部读过原文）

| 来源 | 为什么不行 |
|---|---|
| **中研院全体系**（ASBC、口语语料库、CKIP 词库、广义知网） | 协议第五条明文禁止「字/词频统计」入商业产品 ★ **这同时封死了「自己统计、只散布结果」这条规避路线** |
| **ACLCLP 发行的全部语料** | 需身分证明＋言明不作商业用途＋签约＋付费 |
| **国科会数位典藏 NDAP** | 限个人及非商业目的 |
| **Jun Da 字频表** | 明文禁止商用 |
| **wordfreq 资料** | CC BY-SA 4.0 传染；且把 271 个繁体字在 128 个合并组里抹平（`裡`＝`里`、`麵`＝`面`、`臺`＝`台`）；作者明文拒绝转 CSV；已停止更新 |
| **SUBTLEX-CH** | 简体字幕语料，繁体字形几乎为空；原站 404，许可不传递 |
| **Google Books Ngram 中文** | 实测只有 `chi-sim`，**没有繁体** |
| **THUCTC** | GitHub API 报 MIT，README 却要求商业洽谈 ★ 只看 SPDX 字段会得到相反结论 |
| **腾讯词向量** | 同一句里「CC BY 3.0」＋「for research purpose only」自相矛盾，取严＝限研究 |
| **搜狗** | 付费＋禁止转散布；实验室已下线 |
| **哈工大 LTP／CASIA／SIGHAN** | 企业／商业一律付费或限研究 |
| **rime-ice／fcitx5-table-extra／libpinyin** | GPL-3.0 |
| **北语 BCC（62 亿字）** | ★ 授权条款**未取得** —— 中国这边唯一值得去信确认的大规模字频入口，确认前不可用 |

## 七、这件事的边界

**不做**：整份词表迁移、bigram 接入、符号表、许氏键盘。
理由分别是：会掉语汇（自检 159/257）；两份模型词表差异过大（同上）；
与资料层无关；架构上需要新增有状态的按键层（`keyboard.rs` 的注释警告过）。

**验收的唯一标准**：单音节的平均额外按键（现 **0.405 键/例**）下降，
且没有新增打不到的字。**不看首选正确率。**
