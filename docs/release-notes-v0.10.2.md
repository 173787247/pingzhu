# v0.10.2 — 修掉退格键与下箭头在没打字时被吃掉

## 一句话

没在打字的时候，退格键现在会正常删字；下箭头也不会被无谓地吃掉了。

## 问题

macOS 与 Android 这两个外壳**在任何时候都接管退格键与下箭头**。于是：

```
没在打字，按退格    → 输入法吃掉了，应用程式收不到，字删不掉
没在打字，按下箭头  → 同上
```

同类的输入法不会这样：没在组字的时候，这两个键属于使用者正在编辑的东西。

**Windows 与 Linux(fcitx5) 本来就是对的**，所以这是两个平台上的既有缺陷。

## 怎么发现的

不是有人报 bug，而是**把 Windows 与 Android 接上共享的路由测试向量**之后
自己红的。

`tools/routing-vectors.tsv` 里写着一条规则：

```
\b  composing=0  →  Pass    （没在组字，退格交给应用程式）
\v  composing=0  →  Pass    （没有东西可以浏览）
```

这两条**从写下来就没被执行过** —— 因为只有 macOS 的测试真的读那份向量。
把另外两边接上去的第一个动作，就把它们变成了红的。

（向量本身也有两条写错了 —— 把「没组字」的退格写成 `Backspace`、把「组字中
但没有候选」的下箭头写成 `OpenCandidates`。一并更正。）

## 修了什么

| | 之前 | 现在 |
|---|---|---|
| 退格 | 一律接管 | 组字中才接管，否则交给应用程式 |
| 下箭头 | 一律接管 | 有候选可看才接管，否则交给应用程式 |

四个外壳现在行为一致。

## 测试保护也补上了

原本「改一条规则，四个外壳一起红」这句话**只有 macOS 兑现**。现在三边都读
同一份向量：

```
macos/Tests/Router/main.swift       （本来就读）
windows/tests/test_router.cpp       （本版起）
android/.../RouterTest.kt           （本版起）
```

## 验证

```
Windows   24 条共享向量 · 0 失败 ＋ 原有断言全过
Android   16 项（含新增的闸门断言）
macOS     由 CI 在 macOS runner 上编译
TypeScript 68 项 · Rust 29 项 · 连结检查 657 个 URL 0 损坏
```

## 仍有的缺口

仓库**没有 Windows CI**，所以那一份向量只在本机 `windows/build.sh --run`
时执行；Android 的 workflow 只建 APK、不跑单元测试。也就是说这两个平台的
向量保护目前靠人记得跑 —— 保护是有的，自动化还没有。
