# 快捷输入（自订短语）设计

**状态**：**引擎与网页试打版已实作（2026-11-06）**；外壳（Windows / Linux / macOS /
Android / HarmonyOS）还差**打包**这一步 —— 见文末「实作到哪」。

## 一、问题

打字的人反复输入同一串东西：地址、信箱、统一编号、病历号、公司抬头。台湾的注音输入法
早就把它做成功能：微軟注音叫「使用者造词／短语」，自然輸入法叫「快捷輸入」，RIME 叫
`custom_phrase`。

**这份笔记不发明格式**，只把三个现有做法摊开，指出哪一条与这个引擎的设计相容。

## 二、现有的三种做法

| 产品 | 触发方式 | 存储 | 优缺点 |
|---|---|---|---|
| 微軟新注音 | 打「自订词组」的注音，候选列最前面 | `%APPDATA%\Microsoft\IME\...`（**闭源，格式未公开** ✗） | 与注音一致；格式不可移植 |
| 自然輸入法 | 打**代码**（英数）+ 触发键 | 自家格式 | 代码短、与读音无关 |
| RIME `custom_phrase` | 打**代码**，候选列里出 | `custom_phrase.txt`：`词\t注音\t词频`（**公开、纯文本** ✓） | 最接近本专案的资料哲学 |

`research/04` §4.5.1 抄了 RIME 的实际设定：

```yaml
custom_phrase:
  dictionary: ""
  user_dict: custom_phrase
  db_class: stabledb      # 唯读、不学习
  enable_completion: false
  enable_sentence: false
```

**`stabledb` 是关键**：短语表**不参与学习**。学过的词与写死的短语是两件事，混在一起会让
「我按了什么才会变成这样」变得无法解释。

## 三、与本引擎的相容性

引擎现在有两个资料层：

| 层 | 位置 | 谁写 |
|---|---|---|
| 语言模型 | `bopomofo-lm.tsv`（只读） | 建置时 |
| 使用者词典 | `userdict.tsv`（读写） | 使用者选字时 |

短语表是**第三个**：只读、由使用者手工编辑、不学习。它不该混进 `userdict.tsv` ——
那份是**学习**的结果，会被引擎重写。

### 代码与读音

两条路：

1. **按注音**：像微軟那样，打短语的注音，候选列最前面出现。**与现有的解码流程完全相容**
   （短语就是词库外的额外词条），但代码长 —— 地址的注音打一遍和打地址差不多。
2. **按代码**：打 `addr` 这样的英数代码。**代码短**，但注音输入法平时不接受拉丁字母
   （`feedKey` 会拒绝，见 `v0.10.7` 那次修复），要额外一条路径。

**建议：先做 (1)，因为它是零新机制**。(2) 留作后续 —— 它要决定「什么时候进入代码模式」，
那是一个产品决策，不是实作细节。

## 四、如果按 (1) 做，需要什么

| 位置 | 工作 |
|---|---|
| 引擎 | `data/shortcuts.tsv` 载入；解码时与语言模型一起参与候选，但**分数固定最高**、**不参与学习** |
| C ABI | 无新函数 —— 短语就是词条，`engine_candidates` 自然会带出来 |
| 六种前端 | **零改动**（若短语确实走候选列）|
| 测试 | 短语出现在候选第一位；短语不会被 `userdict` 覆盖；空短语被拒绝 |

**为什么这是最小的一步**：它不需要新 ABI、不需要新 UI、不需要改任何外壳。短语表与语言模型
同一种东西 —— 一份只读的词表。

## 五、还没决定的

1. **短语的长度上限**。候选列一行能显示的字数有限，一条 60 字的地址会撑坏版面。
2. **重复**：同一个注音既有语言模型的词又有短语，谁先？建议短语先（它是「我明确要的」）。
3. **繁体/简体**：短语表存繁体（与引擎一致），输出时走现有的转换边界。
4. **要不要 UI**：纯文本档 + 文件说明，与 `pingzhu.ini`、`layout` 文件一致 —— 这个专案
   的设定一律是档案，不做设定介面（理由见 `windows/README.md`）。

## 六、实作到哪（2026-11-06）

| | |
|---|---|
| `data/shortcuts.tsv` | ✓ 新增，`读音\t词\t分数`，分数用 9（语言模型全是负数，所以永远排最前）|
| TS 引擎 | ✓ `loadDictionary(lm, options, shortcutsPath)` 追加文本；`fromText` 原本就拒绝空词、按分数倒序 |
| Rust 核心 | ✓ `Dictionary::load_with_shortcuts`；`engine_create` 从数据目录找可选的 `shortcuts.tsv` |
| 网页试打版 | ✓ 额外抓一份 `shortcuts.tsv`（找不到就用原样）|
| 测试 | TS 4 条、Rust 2 条：短语排第一、不替换语言模型、空短语被拒、学别的字不影响短语 |
| **外壳的打包** | ✗ **还没做** —— 安装包目前只带 `bopomofo-lm.tsv`／`ts-conversion.tsv`／`bopomofo-chars.tsv`，要把 `shortcuts.tsv` 一起带上；不然装了包的使用者看不到这份档 |

最后一行是这份文档与实作之间的**唯一差距**，写在明处而不是藏着。

## 七、不做什么

- **云端同步**：`research/04` §4.5.4 的建议是「MVP 只做本机」；隐私成本高、没有可信的
  公开格式可对接。这条不在本设计范围内。
- **代码触发**（第 2 条路）：见上，是产品决策，留待后续。
