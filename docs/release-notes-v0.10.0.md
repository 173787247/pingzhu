# v0.10.0 — 尚未成音节的按键显示为注音

## 一句话

打 `gj2` 时组字行从 `ㄕㄨ [2]` 变成 `ㄕㄨ [ㄉ]` —— 括号里显示注音，而不是你按下的那个键。

## 为什么改

括号里原本原样回显按键。于是 `gj2` 显示 `ㄕㄨ [2]`：一个使用者按下的数字
坐在音节旁边，对没读过解码器的人没有任何意义。`su3c` 更糟，泄漏的是内部
诊断符号 `[c]`。

现在渲染注音：`ㄕㄨ [ㄉ]`、`ㄋㄧˇ [ㄏ]`。数字键 `4` 显示为 `ˋ`（大千式上 4 就是
四声）。**该布局上没有注音的按键仍然显示自己，所以不会有东西从画面上消失。**

这不只是美观问题：`ㄕㄨ [ㄉ]` 让「数字键到底在选字还是在组字」变得可见，
使用者不必猜。

## 验证

```
TypeScript   68 项全过（新增 2 项钉住基准工具的抽样性质）
Rust         29 项全过（26 单测 ＋ 差异测试 1529 例 ＋ 交互测试 171 例 ＋ 冒烟）
```

**差异测试钉住「Rust 核心」与「TypeScript 规格」行为一致** —— 本次两边同时
改，1529 例逐例比对；交互测试新增一个形状：**词由第二个音节造出**。

```
ru04      → ㄐㄧㄢˋ        首选「建」（未选字）
ru04gk4   → ㄐㄧㄢˋ ㄕㄜˋ   首选「建設」
空白键     → 送出「建設」
```

它防的不是选错字，而是**过早定案**：若第一个音节完成时就被固定，第二个音节
再也无法回头改它，那么不论候选表多好，`建設` 都打不出来。

## ★ 关于 macOS

**本版不附 macOS 产物。** 原因不是这次没改 macOS，而是 macOS 那条线卡在一个
外部依赖上：**输入法要出现在系统清单里，签章必须是 Apple 签发的 Developer ID**，
而申请该凭证需要付费入会 ＋ 扫脸验证。这一点已由六个变量逐个实测确认：

| 组合 | 结果 |
|---|---|
| ad-hoc，不呼叫注册 API | ✗ 不出现 |
| 自签 ＋ 系统信任，不呼叫 API | ✗ 不出现 |
| 自签，呼叫 API | ✗ `noErr` 但看不到 |
| ad-hoc，呼叫 API（从 app 内部） | ✗ `noErr`，系统列出 0 个 |
| Apple 签发 ＋ 公证 ＋ 呼叫 API | ← 待办，需先取得凭证 |

**macOS 使用者请继续用 v0.9.1**，或在入会完成后自行从原始码构建 ＋ 签章。
相关步骤见 `macos/README.md`。

## 其他修正

- **macOS `install.sh` 在 `spctl` 那一步就退出** —— 它从来没真正装过东西。
  同一个 bug 让每次执行都下载 0.9.1、印出 `REJECTED` 然后结束，把 0.9.0
  留在原地。已修，并把结论指向 `notarize.sh`。
- **macOS 安装文档修正**：原本教人走「免费 Apple ID 就能做」那条路，
  而该路径已被实测推翻（免费帐号在 portal 看不到 Certificates；Xcode Personal
  Team 发的 Apple Development 凭证 `spctl -t exec` 也不接受）。三份文件同步更正。
- **补齐许可全文**：`LICENSES/Apache-2.0.txt`（`data/ts-conversion.tsv` 衍生自
  OpenCC，Apache-2.0 第 4(a) 条要求散布时附上副本，原先只给了连结）、
  `LICENSES/MIT.txt`。并更正 McBopomofo 的版权行为其 `LICENSE.txt` 原文。
- **授权记载修正**：`libchewing-data` 是逐目录多授权（`dict/chewing/` 为
  LGPL-2.1-or-later、`dict/moe/` 为 CC BY-ND 3.0 TW、只有 `dict/chewing_v4/`
  是 CC BY 4.0）；`g0v/moedict-data` 是分层授权而非「无授权」。
