# 注音与拼音的效率比较（量化）

> 一句话结论：**注音的优势比直觉小——词频加权后约少 4–5% 的按键**。而且它不是来自
> 「打字比较快」：组字成本两边几乎打平，差距的一部分来自选字。

这份文件回答一个具体问题：既然拼音的使用者多那么多，为什么还要做注音输入法？
答案是量出来的，不是感觉出来的。

```bash
node tools/zhuyin-vs-pinyin.mjs          # 重现全部数字
node tools/zhuyin-vs-pinyin.mjs --json   # 机器可读
```

---

## 1. 一个必须先讲清楚的直觉

「拼音要拼一串英文字母，一定比注音长很多」——**这只对了一半**。

拼音确实在 `zh ch sh ang eng ong uang iong` 上要拼 2–5 个字母，注音各只要**一键**。
但反过来：**注音几乎每个音节都要多打一个声调键**（一声除外），拼音一个都不打。

而最常用的词，偏偏多半是简单音节：

```
我們  ㄨㄛˇ-ㄇㄣˊ     6 鍵 / women    5 字母     拼音短 1
可以  ㄎㄜˇ-ㄧˇ        5 鍵 / keyi     4 字母     拼音短 1
什麼  ㄕㄜˊ-ㄇㄛ˙      6 鍵 / shemo    5 字母     拼音短 1
自己  ㄗˋ-ㄐㄧˇ        5 鍵 / ziji     4 字母     拼音短 1
問題  ㄨㄣˋ-ㄊㄧˊ      6 鍵 / wenti    5 字母     拼音短 1
台灣  ㄊㄞˊ-ㄨㄢ       5 鍵 / taiwan   6 字母     注音短 1
因為  ㄧㄣ-ㄨㄟˋ       5 鍵 / yinwei   6 字母     注音短 1
這樣  ㄓㄜˋ-ㄧㄤˋ      6 鍵 / zheyang  7 字母     注音短 1
```

全部 74,461 个两字词：**注音较短 29,410（39.5%）、拼音较短 22,637（30.4%）、相同 22,414（30.1%）**。

**常用词偏向拼音短，罕见词与正式词偏向注音短。** 整体是注音略少，但只有百分之几。

---

## 2. 方法

### 资料

`data/bopomofo-lm.tsv`——169,604 条词，每条都带注音读音与词频分数。这是引擎实际使用的
语言模型，不是另外找的语料。

**同一批词、同一组词频，只换一种编码。** 这是最关键的一点：两边的「目标词」完全一样，
所以量到的是编码本身的差异，不是语料差异。

### 拼音读音怎么来

由注音系统性推导（[`engine/src/pinyin.ts`](../engine/src/pinyin.ts)），不是查表：

```
ㄓㄨㄥ  -> zhong      ㄐㄩㄣ  -> jun      （j q x 之后 ü 写成 u）
ㄒㄩㄥ  -> xiong      ㄌㄧㄡˊ -> liu      （韵母缩写）
ㄋㄩˇ   -> nv         ㄕ    -> shi      （空韵写成 i）
```

169,604 条中，注音无法解析 **0 条**，拼音对应缺漏 **17 条**（0.01%，罕见音节）。

**声调一律不计。** 这是对拼音公平的作法——实际上没人在拼音里打声调。
而注音**必须**打（一声除外），这正是差异的来源之一，不是我们额外加的惩罚。

### 五个指标

| 指标 | 定义 |
|---|---|
| 组字按键／字 | 拼出这个词要按几键。注音在大千键盘上一键一个元件；拼音是字母数 |
| 选字按键／字 | 为了拿到想要的那个词，额外要按几键 |
| **有效按键／字** | 组字键 **加上选字键**。这才是实际打字速度 |
| 首选正确率 | 该词是不是它那个按键序列中词频最高的（是的话不必选字） |
| 平均同码候选数 | 一个按键序列平均对应几个不同的词——**模糊度** |

选字成本模型：名次 1 不必选字；名次 r ≤ 10 按一个数字键；名次更后面要先翻页。
模型写在程式码里，可以直接改成你认为合理的值。

### 为什么还要做词频加权

把每个词条等权计算，等于说「打一次〈我们〉和打一次某个罕见词一样重要」。但模型的分数是
log10 机率，`10^score` 就是相对词频。

**这个差别会改变结论的方向。** 最常用的词在拼音里比注音短，等权平均把它们的权重压低了，
反而对注音有利。所以下面两种都报。

**全部 169,587 条都计分，没有抽样**，所以这些是精确值而不是估计值。

## 3. 结果

### 范围二：2–4 音节、一字一音（与 bench.mjs 同范围）

139,163 条。

| | 注音 | 拼音 |
|---|---|---|
| 组字按键／字（等权） | 2.98 | 3.10 |
| 选字按键／字（等权） | 0.03 | 0.11 |
| 有效按键／字（等权） | 3.01 | 3.20 |
| 首选正确率（等权） | **90.67%** | 71.25% |
| 平均同码候选数 | 1.23 | 2.28 |
| **组字按键／字（词频加权）** | **2.94** | **3.02** |
| 选字按键／字（词频加权） | 0.01 | 0.05 |
| **有效按键／字（词频加权）** | **2.95** | **3.07** |
| 首选正确率（词频加权） | **97.98%** | 87.58% |

**有效按键比 1.040——注音少 3.8%。差距的 63% 来自组字、37% 来自选字。**

### 范围一：全部词条（含单字）

单字是同音最严重的部分——`ㄕˋ` 底下有几十个字。这里选字的比重反过来超过组字。

| | 注音 | 拼音 |
|---|---|---|
| 组字按键／字（等权） | 2.99 | 3.10 |
| 选字按键／字（等权） | 0.19 | 0.49 |
| 有效按键／字（等权） | 3.17 | 3.58 |
| 首选正确率（等权） | 77.26% | 60.64% |
| **有效按键／字（词频加权）** | **3.00** | **3.16** |
| **首选正确率（词频加权）** | **89.27%** | 73.99% |
| 平均同码候选数 | 7.25 | 19.52 |
| 相异按键序列数 | 131,031 | 102,835 |

**有效按键比 1.053——注音少 5.0%。差距的 43% 来自组字、57% 来自选字。**

### 方法自我验证

范围二的注音首选正确率（等权）是 **90.67%**。`bench.mjs` 用**完全不同的路径**——实际跑
Viterbi 解码器、抽样 5,000 个读音——量到的是 **90.38%**。

两条独立路径相差 **0.29 个百分点**。这说明「按同一读音内的词频名次」这个便宜的代理指标，
确实抓住了真实解码器的行为。

## 4. 差距从哪里来

**组字只占差距的一部分（38–63%，取决于范围），其余来自选字。**

在 2–4 音节的词上，组字差距只有 2.7%（2.94 对 3.02）；在含单字的全集上，选字差距反过来
更大。两个效应都不是压倒性的。

**模糊度是选字差距的来源。** 平均同码候选数：注音 **7.25**，拼音 **19.52**——**2.7 倍**。

拼音丢掉声调之后，`shi` 要同时代表 是、时、事、市、世、式、视、示、士、势⋯⋯，
注音的 `ㄕˋ` 只代表其中一部分，`ㄕˊ`、`ㄕˇ`、`ㄕ` 各自分开。

而且拼音还会**跨音节边界**碰撞：`xian` 同时是「先」和「西+安」。这种碰撞注音不存在，
因为音节之间有声调与结构把它们分开。

## 5. 这份测量没有证明什么

严谨起见，把限制讲清楚：

**一、量的是编码，不是完整的拼音输入法——而这对拼音是不利的。**
真实的拼音输入法（搜狗、微软拼音）有更大的模型与上下文，可以从语境恢复一部分模糊。
我用「同一按键序列内词频最高者」估计拼音的首选率，这比真实拼音 IME 悲观。
**所以 3.8–5% 是注音优势的上界，不是精确值。真实世界的差距很可能更小。**

**二、没有计入简拼。**
拼音使用者常打缩写（`nihao` → `nh`），这会降低拼音的按键数。注音也有类似的省略写法，
但这份测量两边都没算。要纳入需要另一组实验，因为简拼会**大幅提高**模糊度——那是另一个
取舍，不是免费的。

**三、语料是繁体。**
语言模型从繁体语料建立，所以反映的是那套词汇。比较本身是内部一致的（同一批词、
同一组词频、两种编码），但**不能推论到简体语料**上。

**四、选字成本是模型，不是实测。**
「名次 r 要花几个键」用了一个简单模型。把选字成本设为 0，差距就只剩组字那一部分
（词频加权下 2.7%）——**方向不变，但更小**。

**五、这不是「注音快很多」的证据。**
诚实的结论是：**注音略省，而且省在选字上多过省在拼字上。**
如果你的直觉是「拼音要拼一长串英文字母所以一定慢很多」，资料不支持那个强度——
常用词的拼音其实更短。

## 6. 那为什么还值得做

市场小是事实。但「小」不等于「没有价值」，而且这里有一个常被忽略的结构性理由：

**注音的模糊度低，是因为它把声调写出来。** 声调是中文的资讯，不是冗余。
丢掉它，就要用更大的模型、更多的上下文、更多的选字去补回来——那些成本是**使用者每次
打字都在付**的，不只是开发者付一次。

所以对**已经会注音的人**，注音不只是习惯，是在同等条件下略省力的编码。
省得不多，但每一键都是使用者自己按的。

这个专案要做的，是把那个省力保留下来，同时接到现代的输入法框架上——
而不是要求使用者改用拼音。
