# 08 · 资料层可以自建

> 这份文件要推翻 [04](04-data-and-licensing.md) 可能给人的错误印象。
> 04 花了很多篇幅分析授权，容易读成「这个专案被上游资料绑住」。
> **事实相反：资料层既不是依赖，也不是护城河。**

## 核心论点

注音输入法需要的资料，本质上是四张表：

| 表 | 内容 | 规模量级 |
|---|---|---|
| 读音表 | 汉字 → 注音（含破音字） | 10⁴–10⁵ |
| 词库 | 词 → 读音 | 10⁵ |
| 词频表 | 词 → 出现次数／机率 | 10⁵ |
| 对照表 | 繁↔简、注音↔拼音 | 10³–10⁴ |

**这四张表都可以自建，而且用的都是宽松授权或事实性资料。**
上游开放资料（McBopomofo、libchewing-data）只是**省时间**，不是**能不能做**的前提。

这件事的战略意义：**任何一个上游改变授权、停止维护、或消失，本专案都不会死。**

---

## 一、简繁转换表：可以直接从 Unicode 长出来

[Unicode Unihan 资料库](https://www.unicode.org/Public/UCD/latest/ucd/Unihan.zip)（**Unicode License，
宽松、可商用**）直接提供：

| 栏位 | 笔数 | 用途 |
|---|---|---|
| `kSimplifiedVariant` | **7,291** | 繁 → 简 |
| `kTraditionalVariant` | **6,840** | 简 → 繁 |
| `kSemanticVariant` | 3,563 | 语意异体 |
| `kZVariant` | 159 | 异体字 |

**本仓库实测**（下载 Unihan.zip 后统计栏位分布）：

```
U+346E  kSimplifiedVariant    U+2B748
U+3437  kTraditionalVariant   U+508C
```

所以「简繁转换」有两条独立的路：

1. **OpenCC（Apache-2.0）**——成熟、处理了一对多与词组层级规则，**建议直接用这个**
2. **Unihan 自建**——一万四千条字级对照，作为 fallback 或交叉验证

> ⚠️ 字级对照不足以处理一对多（例如「干」→「干／干／干」需要词组规则）。
> 自建版本要能用，必须额外处理词组层级的例外表。这是 OpenCC 存在的理由。

## 二、读音表与破音字：Unihan 也给了

| 栏位 | 笔数 | 说明 |
|---|---|---|
| `kMandarin` | **44,355** | 汉语拼音读音（含调号） |
| `kHanyuPinyin` | 34,130 | 汉语拼音（多读音） |
| `kTGHZ2013` | 8,105 | 《通用规范汉字表》读音 |
| `kXHC1983` | 11,072 | 《现代汉语词典》读音 |
| **`kHanyuPinlu`** | **3,799** | **读音频次**，例如 `U+4E00 kHanyuPinlu yī(32747)` |

`kHanyuPinlu` 特别有价值：它给的是**每个读音的使用频次**，
这正是破音字排序需要的东西——「一」读 `yī` 三万多次，读其他音少得多，
不需要另外找语料就能排出优先序。

**注音从哪里来？** Unihan 没有直接的注音符号栏位，但拼音 → 注音是
**确定性对应**（不是创作，是事实），一张几百行的转写表就能完成
（RIME 的 `zhuyin.yaml` 做的正是这件事）。所以：

```
Unihan kMandarin (44,355 字)
      + 拼音→注音轉寫表（自建，數百行，確定性對應）
      + kHanyuPinlu（破音字頻次）
      = 完整的注音讀音表
```

**这条路完全不需要 McBopomofo 或 libchewing。**

## 三、词库与词频表：从语料自己算

这是三张表里唯一需要**语料**的，但语料来源很多，而且统计方法本身是公开的。

### 3.1 词频公式（McBopomofo 的公开做法）

```
freq(k) = log10( 2.7^(len(k)-1) × occ(k) / norm )
```

- `2.7^(len(k)-1)`：**长度补偿**。没有它，长词的出现次数永远低于短词，
  分词器会系统性偏好逐字解
- `occ(k)`：词 k 在语料中的出现次数
- `norm`：正规化常数

**这条公式不需要授权**——它是数学。本专案的 `data/bopomofo-lm.tsv` 取用的是
采用这条公式的管线输出，所以分数里已经含了补偿（见 [06](06-engine-design.md)）。

### 3.2 一个必须处理的陷阱：子字串虚假计数

「台湾」出现 1,000 次，其中 800 次其实是「台湾大学」的一部分。
若不扣除，单独的「台湾」会被高估。

McBopomofo 的 `exclusion.txt` 就是为此存在：把「被包含在更长词中」的计数扣掉。
自建管线时这一步不能省，否则短词会泛滥。

### 3.3 断词库：无监督新词发现

没有现成词库时，可以从语料自己长出来：

```
候選 n-gram（n = 2..6）
   ├─ 互信息 MI(x,y) = log [ P(xy) / (P(x)·P(y)) ]     ← 內部結合緊密度
   └─ 左右鄰接熵  H_left, H_right                        ← 邊界自由度
   篩選：MI > 閾值 且 鄰接熵 > 閾值
   ▼
候選新詞 → 人工複核 → 詞庫
```

这是中文资讯处理的标准做法（「新词发现」），工具链在 jieba、HanLP 等专案里
都有可参考的实作。**它输出的是统计量，不是别人的词表。**

### 3.4 语料来源（全部开放）

| 来源 | 授权 | 备注 |
|---|---|---|
| 维基百科／维基词典 dump | CC BY-SA | 量大、涵盖现代用语，需注意 SA 的传染性 |
| 政府开放资料（立法院公报、政府出版品） | OGDL-1.0 | 台湾用语、公文语体 |
| 教育部语料库 | 需个别确认 | 华语教学语体 |
| 开放街图、开放原始码注解 | ODbL／各专案 | 专有名词 |

> ⚠️ **法律要点（非法律意见）**：词频统计的**输出**（「某词出现 N 次」）
> 通常被视为事实性资料，而事实不受著作权保护。但「以受著作权保护的语料
> 产出统计量」是否构成衍生作品，各司法管辖区见解不一。
> **采用受 CC BY-SA 之类传染性授权的语料时，必须先确认这条界线。**
> 若要有完全干净的来源，应以政府开放资料（OGDL）与自有语料为主。

## 四、这对专案意味著什么

### 对授权分析（[04](04-data-and-licensing.md)）的修正

04 的文件读起来像是「我们在别人的授权缝隙里求生」。正确的理解是：

| 情境 | 对策 | 成本 |
|---|---|---|
| 上游都健在（现在） | 直接用 McBopomofo（MIT） | 0 |
| McBopomofo 改变授权／消失 | 换 libchewing-data（CC BY 4.0） | 低（格式转换） |
| 两个都不可用 | **从 Unihan + 自建语料重建** | 中（数周） |

**第三条路的存在，让前两条路的谈判地位完全不同。** 我们接受 MIT 是因为它方便，
不是因为没有它就做不下去。

### 对「护城河」的修正

自然输入法的护城河**不是资料**。它的词库可以从语料重建，
它的引擎（v10–v13）甚至建在开源的 OpenVanilla 与烟草注音引擎上（见 [01](01-competitive-analysis.md) §5.1）。

它真正的护城河是 **35 年的脉络会意法调校**、**桌面整合的细节打磨**、
**司法院体系的实务地位**、以及**使用者 30 年累积的个人词库与肌肉记忆**。
这些都不是抓资料能复制的——这也正是 [05 路线图](05-roadmap.md) 把
「个人化学习」排在很前面的原因。

### 具体行动

| 项目 | 何时做 |
|---|---|
| 把 Unihan 读音表接入，作为读音的第二来源（交叉验证 + 补罕用字） | M2 之后 |
| 用 `kHanyuPinlu` 建立破音字优先序 | M2 之后（可取代教育部《一字多音审订表》，授权更干净） |
| 自建简繁表作为 OpenCC 的交叉验证 | M8 |
| 自建语料管线（MI + 邻接熵新词发现） | 当需要台湾本地新词时（M8+） |

**现在都不做。** 目前的资料（169,604 词条）已经足够跑出 100% 读音准确率
（见 [06](06-engine-design.md)），自建资料层是**保险**与**未来的扩充路径**，不是当务之急。

> 这一节的价值在于：当有人问「你们的词库是跟人家拿的，那授权怎么办」时，
> 答案是「**我们可以自己做，而且已经知道怎么做、用什么来源、公式是什么**」。
