# v0.10.8 — 不打声调也能打出字来

## 一句话

注音使用者大多不打声调。以前，末音节没有声调时它会**悬在缓冲区里**，一个字也送不出；
现在末音节交给语言模型选声调。另外修掉了一个被它暴露出来的测试判据错误。

## 一、`su` 打不出「你」

索引是按「音节 + 声调」建的。所以末音节只打 `ㄋㄧ`（不打 ˇ）时，这个音节**不在索引里**：

```
su        → [ㄋㄧ]        什么都送不出
ji394su   → 我愛          后面的「ㄋㄧ」留在缓冲区
```

`research/04` §4.4 早就把「省略声调」列成**必做**，理由写得很直白：绝大多数使用者不打声调。

现在末音节没有声调时展开成四种声调，让语言模型挑：

| 输入 | 此前 | 现在 |
|---|---|---|
| `su` | 悬空，送不出 | ㄋㄧˇ → **你** |
| `ji394su` | 我愛 | **我愛你** |
| 你好 + `bs` | 你蒿 | **你好** |
| 你好 + `g` | 你好師 | **你好是** |

## 二、为什么只做末音节

先做的是**全量**展开 —— 每个无声调音节都展开。两个后果：

- 候选组合按 4 的幂增长：测试套件 **2.1 秒 → 38.5 秒**
- 既有场景「溫純」变成「文純」—— 那不是改善

改成**只对末音节**：覆盖真正需要的场景，成本限定在每次输入 4 倍一次，套件 3.7 秒。
中间的无声调音节仍由下一个音节的首键收尾、读作一聲。

## 三、被它暴露出的一个测试判据错误

`buildTestSet` 最后有一道往返检查：一个读音的按键流解回来必须等于原读音，否则那条样本
算测试工具的假象（按键流不带音节边界，`ㄕ-ㄨˋ` 会解成 `ㄕㄨˋ`）。

上面那个改动之后，`ㄅㄚ` 这种省略声调的读音解回来变成 `ㄅㄚˇ` —— 往返失败，**48 条样本
被悄悄滤掉**，样本数从 1,500 掉到 1,452。这道检查关心的是**音节边界**，不是声调；改成
比对时忽略声调之后，1,500 条回来了。

## 四、基准的数字变了 —— 而且这次是对的

| | 改动前 | 改动后 |
|---|---|---|
| 样本 | 2,862 | **3,000** |
| top-1 | 84.31% | **80.47%** |
| 带声调命中 | 2,413 | **2,414** |
| lost to decomposition | 0 | **137** |
| 单音节 | 5.98%（18/301）| 4.66%（18/386）|

**带声调的 2,413 条一条没变。** 掉的是新进来的 138 条省略声调读音 —— 它们本来就对应
多个声调（`ㄅㄚ` 在一聲是巴、在 ˇ 是把），没有唯一答案。基准以前报的是**滤掉难例之后**
的分布，现在报真实分布。

README 里那段转录（`bench.mjs 5000`）按当前代码重跑了：78.82% → **76.80%**，
`lost to decomposition` 0 → **219**，单音节 5.38% → **4.46%**。原来那句「5,000 个样本
零真实解码失败」也不再成立，一并改写。**那是转录，不是示意** —— 代码变了就该重跑。
