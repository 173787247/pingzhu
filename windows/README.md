# 平注 PingZhu — Windows 可携版注音输入法

**这是可以现在就用的版本。** 托盘常驻、全域键盘钩子、候选视窗、字元注入。

```
C:\Users\<你>\pingzhu-build\
├── pingzhu-ime.exe           ← 執行這個
├── pingzhu_core.dll          ← Rust 引擎（解碼、詞庫、學習）
├── pingzhu-router-test.exe   ← 按鍵路由測試
├── pingzhu-engine-test.exe   ← 引擎整合測試
├── pingzhu-userdict.txt      ← 你的學習紀錄（首次離開時產生）
└── data\
    └── bopomofo-lm.tsv       ← 169,604 條語言模型
```

## 操作

| 按键 | 行为 |
|---|---|
| `Ctrl+Alt+Z` | 切换中文／英文（托盘左键也一样） |
| 托盘右键 | 选单（切换、结束） |
| 注音键 | 打字（大千式：`su3cl3` = 你好） |
| `空白` | **送出**（组字中）；候选视窗开启时=下一页 |
| `↓` / `↑` | 开启／关闭候选视窗 |
| `1`…`9`、`0` | **选字模式开启后**选第 1…10 个 |
| `←` `→` | 移动候选游标 |
| `Backspace` | 退一格 |
| `Enter` | 送出 |
| `Esc` | 清空 |

**空白键是送出。** 打 `su3cl3` 再按空白，直接得到「你好」——这是台湾输入法的标准行为。
要挑字就先按 `↓` 开启候选视窗，那时数字才是选字键，空白则变成翻页。

**为什么数字要先开候选视窗？** 因为大千式键盘上 `1234567890` **本身就是注音键**
（1ㄅ 2ㄉ 3ˇ 4ˋ 5ㄓ 6ˊ 7˙ 8ㄚ 9ㄞ 0ㄢ）。如果数字直接选字，`su3cl3` 就永远打不出来。
真实输入法（微软新注音、自然输入法）也是同样的处理。

## 这是什么、不是什么

**是**：一个不需要安装、不需要管理员权限、不需要 COM 注册就能跑的输入法。
多数应用程式可用（记事本、浏览器、Office、Electron 应用）。

**不是**：TSF 文字服务。所以它不会出现在语言列，也**无法对以管理员权限执行的视窗输入**
（UIPI 限制，不是 bug），对读取原始输入的游戏也无效。

TSF 版本是下一步：同一份引擎、同一个候选视窗，加上 COM 注册。

## 语言列版（TSF 文字服务）

```bash
install-languagebar.cmd        # 雙擊，會跳 UAC
```

装好后 **Win+Space** 就会看到「平注注音输入法」。移除用 `uninstall-languagebar.cmd`。

和可携版的差别：

| | 可携版 | TSF 版 |
|---|---|---|
| 进语言栏 | ✗ | ✓ |
| 中／英切换 | 自己管（Ctrl+Alt+Z） | 作业系统管（Win+Space） |
| 对管理员权限视窗 | ✗ UIPI 阻挡 | ✓ |
| 送字方式 | `SendInput` 注入 | 直接在文件组字 |

**Windows 是「每个应用程式各自记住输入法」的**，所以要先把游标放进目标视窗，再按 Win+Space。

### 升级时必须重新启动应用程式（这一条我原本写错了）

DLL 档名带版本，但**光靠切换输入法不会载入新版本**。

COM 的行为是：某个 CLSID 的进程内伺服器**一旦在该行程中载入**，之后建立该物件会
**直接复用已驻留的模组，不会重新读注册表**。Windows 也不会替换已映射的 DLL 映像。

所以升级后：

| 情况 | 结果 |
|---|---|
| 已经载入过旧版的程式 | **必须重新启动**才会拿到新版 |
| 从未载入过的新程式 | 直接拿到新版 |
| 档名带版本号 | 让新旧两版能同时存在，不会卡住安装 |

这不是我们的实作缺陷——所有行程内 COM 伺服器都一样，这也是商业输入法安装完
会要求你重新启动的原因。

装完之后如果觉得「怎么还是旧的行为」，先确认那个程式是不是在安装前就开著。

### DLL 档名带版本号，不是装饰

`pingzhu-tsf-0.5.1.dll`、`pingzhu_core.dll` —— Windows 会把已载入的 DLL **锁住整个行程的生命周期**。输入法被载入到记事本、Explorer、微信⋯⋯意味著升级时根本无法覆写档案（会得到一句裸的 `Permission denied`）。

解法有两个，这里都用上了：

1. **文字服务的 DLL 档名带版本**——新版本注册新档名，旧档留给还映射著它的行程
2. **建置时先让位再放置**——Windows 允许**重命名**被锁住的档案，只拒绝覆写

这条规则是被踩出来的，不是设计出来的。

### 诊断记录档

`pingzhu-tsf.log`（在 DLL 旁边）。文字服务跑在别人的行程里，出错时**什么都不会说**——按键只会静静地穿过去，使用者看到的是「这个输入法完全没反应」。

记录的内容：激活、引擎载入结果、主机行程名、第一次按键是否抵达。
**不记录的内容：按键、组字、送出的字。** 会记下你打了什么的日志就叫键盘记录器，不管意图是什么。

## 设定：`pingzhu.ini`

两个外壳都读 DLL／EXE 旁边的 `pingzhu.ini`。第一次执行会自动产生一份有注解的预设档，
所以设定是可发现的，不是秘密。

```ini
# 輸出字形：traditional（繁體）或 simplified（簡體）
# 輸入的注音與詞庫不受影響，只改變送出的字。
output = simplified
```

改完存档，下次切换输入法（TSF 版）或重新执行（可携版）就生效。
可携版也可以直接从托盘右键选单切换，它会把选择写回档案。

**为什么是设定档而不是设定介面？** TSF 文字服务被载入到别人的行程里，没有自己的视窗，
也就无处安放介面。一个能用记事本编辑、能 diff、能跟著目录一起搬走的文字档，是诚实的答案。

### 繁简转换是输出转换，不是两份资料

引擎内部**全程使用繁体**：读音、语言模型、使用者词库都以繁体词为键。转换只发生在
输出的边界上。这让两件事成立：

- 使用者切回繁体时，**学过的词还在**——因为从来没有被改写过
- 只需要维护一份对照表，而不是一份转换过的 17 万条模型（那会和原表逐渐分歧）

对照表来自 [OpenCC](https://github.com/BYVoid/OpenCC)（Apache-2.0）。
**词组优先于单字**：`乾坤` 必须保持 `乾坤`，不能变成 `干坤`——OpenCC 有 124 条
「键值相同」的词组，存在的目的正是挡住这类单字规则。把它们当成无操作丢掉，
会在表格最想保护的地方安静地转错。

## 从 WSL 重新建置

```bash
bash windows/build.sh                    # 建置到 /mnt/c/Users/$USER/pingzhu-build
bash windows/build.sh <staging> --run    # 順便跑路由測試
```

建置流程有两个工具链，理由很具体：

| 部分 | 工具链 | 为什么 |
|---|---|---|
| Rust 核心 | `x86_64-pc-windows-msvc`（从 WSL 驱动） | 与外壳同一个 CRT，且全在 WSL 内可脚本化 |
| C++ 外壳 | MSVC（`windows/build.bat`） | Windows 原生工具链，`msctf.h` 等都在 SDK 里 |

从 WSL 让 cargo 驱动 Windows 连结器需要两个技巧（见 `~/.local/bin/msvc-link.sh`）：

1. **路径翻译**：rustc 产出 POSIX 路径，`link.exe` 读不懂，用 `wslpath` 转。
2. **环境变数**：WSL 会改写看起来像 Windows 路径清单的环境变数，所以 `LIB`/`INCLUDE`
   传不过去。解法是整个连结都在 Windows 侧跑，由产生的 .bat 自己呼叫 `vcvars64.bat`。

外壳用 `LoadLibrary` 载入 DLL 而不是静态连结，所以 DLL 不在或 ABI 版本不符时，
它会给你一句可读的错误，而不是呼叫到错误的函式签章。

## 测试

```bash
# Windows 原生，透過真實 DLL
pingzhu-router-test.exe      # 按鍵路由：數字何時組字、何時選字
pingzhu-engine-test.exe data # 引擎整合：你好／我愛你／萬丹／學習

# Linux 端（引擎本體）
cd ../engine && node --test "test/*.test.ts"    # 40 項
cd ../core-rs && cargo test                     # 16 單元 + 2 差異化
```

`pingzhu-engine-test.exe` 在开发过程中抓到一个真实缺陷：`engine_create` 原本不附带
使用者词库，只有在词库档**已存在**时才装上——也就是说**全新安装的使用者永远学不了字**。
现在 `engine_create` 一律附上一个空的词库。

## 已知限制

1. 不是 TSF，不进语言列，管理员视窗无效。
2. 注入是 `SendInput` 的 Unicode 字元，少数应用（游戏、部分终端机）可能收不到。
3. 没有词库汇出汇入的介面（档案就在旁边，纯文字，可以直接编辑）。
4. 仓颉／拼音等模式尚未接上（引擎目前只有注音）。
